## 3.5 路线B（frida-java-bridge 语义修复，2026-08-25 实现链完成——待编译/真机验证）
- **目标**：Java.perform/Java.use().implementation frida 语法跑在已验证官通（LSP.hook→HookRouter→libxposed LSPlant）上；实现链 t5(设计)+t6(shim/JS)+t7(HookRouter replace+cpp 同步回调)+t9(async this.method 桥) 全部完成并静态验收（check-kt 双绿）。
- **关键事实（实核）**：libxposed Chain 无 setArgs/setResult——改参=proceed(args)、返回覆盖=intercept 返回值、不 proceed=跳过；C→JS 通道=gum_script_post + 标准 frida:rpc 协议（runtime message-dispatcher 自动调 rpc.exports + Promise reply），全公共 API，无 extern 私有；GumScriptTask sync API 仅源码层不在 devkit 头。
- **B1 语义定案**：fn 返回 undefined=自动 proceed（观察）；非 undefined=替换返回（跳过原方法）；async fn 内 await this.method(...) 可用（lsp.rpc_inner 嵌套，cpp 时序已证明两种到达顺序安全）；同步 fn 走桥不抛错；this 非方法属性访问抛可读错误；this.method 传参被忽略（原参 proceed）→ 自定义参数=B2；overload 精确选择=B2。
- **线程模型**：全局串行 + condvar ≤500ms/阶段；超时/CAST_FAIL/JS_ERR→proceed 兜底（目标不崩）；pending owner 线程回收，clear_all 只标记防 UAF。
- **t7 顺带闭环**：t2 P0#1（HookRouter overload key=cls#method#sig#tag 单 handle）已修。
- **文档**：docs/RouteB-Facts.md（cap 实核）、docs/RouteB-Plan.md（t5 实现方案）、docs/RouteB-Verify-List.md（真机验证清单：R1-A 探针+三场景+检查点）。
- **真机验证：✅ 已通过（2026-08-25 18:57）**——观察/替换返回/async 嵌套/心跳全绿、零 REPLACE_TIMEOUT；最终根因与修复：①JS→C reply 卡 default gmain context（t10 泵修复）②frida send 信封未解（unwrap_send_payload）③sqlite 初始符号被 gc-sections 回收（CMakeLists --undefined retention）。
- **B1 边界 → B2 已补**（2026-08-25 t15 交付）：①自定义参数调用原方法（rpc_inner args → proceed(convArgs)；对象占位/不符→安全回退原参）②overload 精确选择（sigs 数组+JVM 描述符匹配，缺省=挂全部）③回归修复：`return this.method(a)` 双层执行 bug（innerExecuted 复用）；**对象代理仍为后续项**（__obj 占位）。
- **t14（注入提示）**：冷注入路径绕过 TargetIpcServer.loadScript 致永不提示 → InjectHintStore 双通道（remote prefs hint_inject）+ LSPFRIFAModule 冷注入成功 Toast（读 remote，主线程）。
