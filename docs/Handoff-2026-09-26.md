## 1. 项目定位
Android **Xposed/LSPosed + Frida GumJS** 注入框架模块：目标应用内跑 **Frida JavaScript 脚本**，语法与 frida-java-bridge 兼容（`Java.perform/use/implementation/overload`），引擎复用 LSPosed 的 LSPlant；UI = Miuix（HyperOS 风格）Compose。设备：小米 23013RK75C / Android 15 / HyperOS / LSPosed 2.1.1（API 102）。

## 2. 架构现状（最终态）
```
目标 App 进程                             宿主（模块 App）进程
LSPFRIFAModule(onPackageLoaded)            Compose UI (Miuix 0.9.4-rc01)
  → hook Instrumentation.callApplicationOnCreate   ├ detail(插件视图/入口行) editor/logs pages
  → GumJsBridge (frida-gumjs 17.25.2 QuickJS devkit) ├ ScriptStore/LogStore/IPC (AIDL×2)
  → LSP.hook → HookRouter → libxposed hook()(LSPlant)└ TargetIpcServer(Binder 实体)
        ▲ 回调回 JS：frida:rpc 协议（message-dispatcher 自动 reply）+ 出站泵(默认 gmain context)
注入提示/脚本/启用状态：remote prefs 双通道（框架存储 lspfrifa_config: enabled(StringSet)/script.<pkg>/hint_inject）
```
- 模块入口：`META-INF/xposed/java_init.list`；`module.prop` minApiVersion=82 + targetApiVersion=102
- 官方通道已验证：`[lsp-hook] ARMED/HIT`（LSPlant 在 HyperOS A15 触发）
- **B1/B2 全链路**：JS→send→HookRouter（目标进程）→LSPlant→intercept→args 编码→C→JS（frida:rpc call）→JS 回调（user fn）→自动 reply（dispatcher）→C 解信封+命 pending→signal→Kotlin 按 `{over,r}`（proceed/覆盖/__inner 嵌套循环）→ 完成。

## 4. 关键坑位库（后续开发必读——全部实核）
| 坑/事实 | 正确做法 |
|---|---|
| libxposed Chain | 无 setArgs/setResult——改参=proceed(Object[])，返回覆盖=intercept 返回值；不 proceed=跳过原方法 |
| frida send 信封 | JS send 消息 = `{"type":"send","payload":X}`（信封！）——cpp 解析必须 unwrap（曾只认裸数组→全超时；已修 unwrap_send_payload） |
| 出站泵 | JS→C 出站（send/reply/console）附着创建线程 thread-default → 全局 g_main_context_default()——nativeCallJs 等待环必须泵 default context（10ms 切片+500ms 预算；已修） |
| 符号 GC | frida 内置 sqlite 被 gc-sections 回收 → 运行期 `_frida_sqlite3_initialize` pc=0 SIGSEGV → CMakeLists `--undefined=_frida_sqlite3_initialize`（已修） |
| GCC 包装 | `g_str_equal` 等在 devkit 单头只有宏无原型 → 自实现（lsp_str_hash/equal） |
| Kotlin raw string | `"""…"""` 内 `$` 仍模板展开（`\$` 无效！）→ 用 `"${'$'}"`；曾致 shim 文件被多层手术破坏（教训：先 git 基线再手术） |
| devkit 大小 | libfrida-gumjs.a 约 370MB（debug 信息）——**不入库**，README 用 fetch 脚本拉取（17.25.2 arm64/arm tarball） |
| CMake 环境（RV2IDE） | SDK cmake/3.22.1 已替换为自包含 4.1.2 内容（bin+lib 需强覆盖 cp，`cp -n` 会跳过！）；缺 librhash.so.1=LD 路径/旧文件；MTE 链接崩溃=环境偶发（重试/释放内存/单 ABI 应急后恢复双 ABI）；ninja dirty-manifest=时间戳漂移（清 .cxx 重跑） |
| 构建 | 建议 AndroidIDE **运行任务面板**；`cmake.dir=...` 占位曾致 AGP 走 usr/bin/cmake（已修复删除） |
| 符号表检查 | check-kt.sh 规则（含未导入符号检测 tools/check-imports.awk）；cpp 括号校验**必须排除 char 字面量**（`'{'` 假阳性） |
| 验证脚本规范 | 默认**JS 侧节流**（一次日志）；避免高频方法（currentTimeMillis 刷屏教训） |
| **git 提交（2026-09-26 实核，严重）** | `/sdcard`（FUSE/sdcardfs）**不支持 git 默认的硬链接式对象写入** → 任何 `git add/commit` 报 `unable to write file .git/objects/xx/…: No such file or directory`（可复现于全新空仓库，与仓库损坏无关）。**修复：`git config core.createObject rename`**（每个克隆都要设一次，非全局）。失败残留 `.l2s.tmp_obj_*` 临时对象 → `git fsck` 报 `bad sha1 file` → `find .git -name '.l2s.tmp_obj_*' -delete` 清理。**既往 2 个提交（`99eec0d`/`4f7b777`）很可能是在能写硬链接的环境（Termux/iso-git）里做的。** |
